# 研究／评审职责重构：快照存档 + 两层制研究文件

日期：2026-08-09
状态：设计已裁定，待实施计划

## 问题

研究与评审此前读页面都只经 `WebFetch`。该工具自己的说明写着 "converts the page to
markdown, and **answers `prompt` against it using a small fast model**"——它从不把页面
还给调用者，返回的是一个小模型读完页面后写的答复。于是：

1. 研究阶段登记的「正文原话」是小模型转述的再转述，不是原文字节。
2. 评审阶段的「独立核查」读到的同样是模型答复，用它去推翻研究文件，方向上并不比被推翻者可靠。
3. `## 事实`／`## 当事方` 是自由散文，「见信源5」是一句声明而不是指针——没有任何机械手段
   能确认某句话确实出自某条来源。

已发生的后果：260731-1 把某报道的**标题措辞**标成当事人原话（评审碰巧抓住）；
260605-3「近乎逐字又改写」混进叙述节；260725-2 `当事方` 概括句与 `事实` 时间线对不上；
260604-3 研究文件宣称「查不到」而该事实就在它自己引用的材料里（五次复现）。

已落地的第一步：`src/srcfetch.py` 走裸 HTTP／无头浏览器取原始 HTML（模型不介入），
`research_linter` 据此对标 `正文原话` 的摘录做逐字核对（commit `1494969`）。本设计把
这一步扩成完整的证据链。

## 目标与非目标

**目标**：研究文件里的**一切内容都必须有出处**——可回指到某条快照的某处，并可被机械核验。

**非目标**（明确不动）：
- 不降低 `blog-reviewer` 的独立性。它的价值正在于不共享研究阶段的信息通路；本次重构
  不得把它变成「核对研究文件」。它自己选哪些 URL 去查，一律不受研究文件影响。
- 不迁移存量。`_pipeline_archive/` 的历史研究文件、以及在途的 260630-1／260731-1 照旧格式收尾。
- 不改草稿格式。`[E]` 编号只存在于研究文件，不进草稿、不进已发布文章。
- 不改 `blog-writer` 的工具列表（`Read`／`Grep` 本就在列）。

## A. 快照层

### 存储与生命周期

    _pipeline/snapshots/{YYMMDD}-{N}/{host}-{hash8}.txt

**入库**（现在的 `_pipeline/.srccache/` 扁平缓存作废，从 `.gitignore` 删除）。理由：快照是
文章的证据底本，不是校验用的临时文件。网页会改会删，缓存丢了证据链就断了——已发布文章
的每一句都要在几年后仍能回溯到当时抓到的原始页面。同一 URL 被两个事件引用就各存一份；
8KB 的重复不值得引入二级缓存。

文件头保持现状：`# SOURCE: {url}` / `# FETCHED: {iso8601}`，空行后是正文。文件名用
`{host}-{sha1[:8]}` 而非纯哈希，便于人肉浏览。

事件进入终态时，`src/utils/archive.py` 的 `_EVENT_STAGES` 加入 `snapshots`，快照目录随
research／draft／review 一并进 `_pipeline_archive/`。

### `srcfetch.py` 新增

| 参数 | 作用 |
|---|---|
| `--event {YYMMDD}-{N}` | 决定落到哪个事件目录；`load()` 同样按事件解析 |
| `--from-research <file>` | 读出研究文件 `## 信息来源` 的全部 URL，一条命令批量落快照 |
| `--refresh` | 强制重抓覆盖旧快照 |

`--from-research` 不是便利功能而是必需：没有它，agent 要手敲十几个 URL，必然漏。
`--refresh` 同理：快照带抓取时间，评审若命中研究阶段几天前的旧快照，用来查「有没有
更新进展」就是错的。

### 抓不到时的豁免

来源行尾写 `快照失败：<原因>`。该来源：

- **不得**作为任何逐字引文的依据（不能被 `正文原话` 摘录引用）
- **不得**单独支撑一条事实（必须与另一条有快照的来源并列）

两条都由 linter 拦。把「抓不到」从静默降级变成开官声明，且后果传到下游。

## B. 研究文件两层制

### 新结构

`## 信息来源` 退化为**纯书目**——日期、原始署名媒体、真标题、URL、快照状态。摘录不再
放在行尾（一件事一个归宿）。新增 `## 摘录` 节。

**文件内节序**：`## 事实` → `## 当事方` → `## 信息来源` → `## 摘录` → `## 资产`。
人先读叙述，摘录层是被回指的参考材料。下面的示例块**按讲解顺序排列，不是文件顺序**。

```
## 信息来源
- 2026.07.31，极目新闻（记者柳琛琛）。*标题*。https://… — 快照 2026-08-07（4211字）
- 2026.07.31，某站。*标题*。https://… — 快照失败：25s 无响应

## 摘录
[E1] 信源3 · 正文原话 · 2026-08-07
我不认识他，他从没联系过我
[E2] 信源3 · 第三人称转述 · 2026-08-07
青岛市公安局李沧分局行政处罚决定书显示，一男子在群内转发牟某文照片搭配不雅视频进行侮辱
[E3] 资产 260731-1-立案截图.jpg · 图上转录 · —
案由：名誉权纠纷　状态：待审核

## 事实
- 2025.10.12：李沧分局对一男子作出行拘5日决定[E8]，该男子手写悔过书致歉[E9]。

## 当事方
**牟倩文**：青岛保时捷中心销售[E4]，2025年卖出192台[E5]。自述曾有轻生念头[E17]。
```

摘录形态四种：`正文原话`／`第三人称转述`／`标题`／`图上转录`。编号 `[EN]` 全文件唯一、
只增不改（update 模式追加新编号，**不得重编**，否则历史引用全部错位）。

### `research_linter` 新闸口

| 检查 | 级别 |
|---|---|
| 每条摘录逐字出现在其信源的快照里（经 `srcfetch.normalize` 归一） | FAIL |
| 摘录形态在四种之内 | FAIL |
| `信源N` 能解析到书目行；`图上转录` 指向 `## 资产` 实有文件 | FAIL |
| `事实`／`当事方` 每一句至少带一个 `[E]`（按 `。！？` 切分；切出的片段去掉 `[E]`／标记后 CJK 少于 8 字的不算句子，避免小标题、分组行误报） | FAIL |
| 被引用的 `[E]` 编号存在 | FAIL |
| `事实`／`当事方` 里长度 ≥8 字的引号跨度，必须逐字命中某条摘录 | FAIL |
| 标 `快照失败` 的来源被 `正文原话` 摘录引用 | FAIL |
| 标 `快照失败` 的来源单独支撑某条事实（该句无其他 `[E]`） | FAIL |
| 摘录无人引用（孤儿） | WARN |
| 书目行有 URL 但既无快照也无 `快照失败` 标记 | FAIL |

最后一条取代现在的「无快照 WARN」——上一轮全量扫出 82 条无快照 WARN，全部被忽略，
证明 WARN 在这里不起作用。

`事实`／`当事方` 里**只有两种句子豁免 `[E]`**：

- `**查证失败（评审vN-问题K）**：…` —— 定义上就没有出处
- `**检索记录**：检索至 X 日未见…` —— 对研究者自身检索行为的陈述，任何信源都无法作证

现有的 `NARRATIVE_SECTIONS` 伪引用检查（「自称正文原话、只见于来源标题」）被上表第 6 条
**吞并**：新格式下叙述节的任何引号跨度都必须命中摘录层，而摘录层本身已逐字核过快照。

### 新旧共存

`research_linter` 按文件**有无 `## 摘录` 节**分派两套规则。有＝新格式走上表；无＝走现有
规则原样不动。在途的 260630-1／260731-1 因此不受影响，不必为重构停摆。

## C. 三个 agent 文件

### `blog-researcher`——重写主干

职责从「读页面后转写」改为**抓取快照存档 ＋ 整合**。新流程：

1. Step 0 同案查重（不变）
2. WebSearch 发现 → 定源、写书目行
3. `srcfetch --event {YYMMDD}-{N} --from-research <file>` 批量落快照
4. **Read 快照** → 摘出 `## 摘录`（逐字 + 形态判定 + 信源号）
5. 整合 → `## 事实` 时间线、`## 当事方`，每句挂 `[E]`
6. 资产抓取（不变）
7. Lint gate

**`WebFetch` 在研究阶段降级为发现与分诊**——读搜索结果页、判断某 URL 值不值得抓，
以及 DuckDuckGo html 端点兜底。**不得作为摘录来源**。摘录只能来自快照。

CLAUDE.md 待办记录的空引用（该文件「见 Lint gate」指向一个当时不存在的检查）在此解决。

**体积约束**：本次重写按**净增 ≤ 0** 落。该文件现 169 行，其中「摘录完整性不许省略号
截断」「形态标注两个方向都错过」等长段落存在的理由正是没有机械闸口、只能靠文字反复
叮嘱；闸口落地后这些段落缩到一句加「linter 拦」。符合 CLAUDE.md《规则增长预算》。

### `blog-reviewer`——加两处，独立性不动

- 开 `类型：事实` 问题且引用外部来源作反证时，该来源必须先 `srcfetch --refresh` 落快照，
  `<!-- [REVIEWER] -->` 里的引文逐字取自快照。**断言才要证据，怀疑不要**——只是提问
  「这条存疑，请研究阶段核实」不需要快照。
- 新增一步：研究文件凡写「未见报道／查证失败／仅自媒体转述／无最新进展」的，去本事件
  快照集 `grep` 一遍再放行。这一步接住 260604-3 那类「研究文件漏读自己抓来的材料」，
  成本极低，且不把形态判定复制进写手。
- 第 3 步（引文逐字存在性比对）的基准从 `## 信息来源` 改为 `## 摘录`；「只有 `正文原话`
  摘录能作灰字依据」这条不变，只换节名。

### `blog-writer`——三处

- 灰字依据从 `## 信息来源` 改为 `## 摘录` 里标 `正文原话` 的条目
- 新增**可读不可取**条：可以 `Read`／`Grep` 快照来**核对**研究文件有没有转写走样或遗漏，
  但进正文的一律必须追到 `[E]`；发现缺口照旧上报、不自行补
- 缺口上报升级为带证据：「`[E7]` 摘录漏了后半句，快照里原句是 X」，而不只是「这里有个洞」

**为什么写手仍不得从快照直接取材**（旧理由「写手没有网络工具」已不成立——快照是本地
文件；换成下面两条）：

1. **形态判定不能复制到写手身上。** 快照是剥了标签的纯文本，一句话在里面就是一串字；
   它是当事人带归属的直接引语还是记者的叙述句，要读上下文判断。这个判断正是研究阶段
   存在的理由，也正是反复翻车处（260717-1／260721-3／260724-2／260731-1 四次）。让写手
   再做一遍，等于同一判断在两个 agent 里各做一次、中间没有闸口。
2. **评审第 3 步会退化为猜测。** 它现在是硬判据：草稿里的逐字引用命中不了摘录层＝写手
   编的。写手一旦可以合法地从快照直接取，每次命中失败都变成「也许它抄自某份快照」，
   评审得 grep 十一份快照才能证伪。

## 已知代价与风险

1. **研究 agent 的读取量上涨。** 它必须 Read 快照才能摘出逐字片段（现均 8.4KB × 约 11 条
   ≈ 30–45k token/事件）。这部分替换掉原来的 WebFetch 调用，净增有限但确实是涨的。
   若成为瓶颈，缓解方向是 `srcfetch` 更狠地剥站点 chrome，而不是回退到模型转述。
2. **`图上转录` 是唯一诚实的缺口。** 图是二进制，字节比对不成立；资产文件本身已归档，
   指针成立，但转录准确性无法机械核。标出来而不是假装核过。
3. **每句挂 `[E]` 可能噪音偏大。** 尤其 `## 当事方` 的长概括段。先按每句一挂落地，
   实跑两三个事件后再看要不要放宽到每分句。这是可回退的参数，不是结构。
4. **仓库体积。** 约 90KB/事件，一年约 33MB。纯文本、可压缩，可接受。
5. **快照与页面漂移。** 快照是抓取时刻的字节；页面事后被改，快照与线上不一致是**预期
   行为**——那正是存档的意义。评审若发现漂移，那本身是一条事实（报道被修改过）。
